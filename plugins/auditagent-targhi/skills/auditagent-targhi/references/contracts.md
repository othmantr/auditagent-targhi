# JSON contracts (controller version 0.1)

Use Python 3.11+. IDs start with a letter and contain letters, digits, underscore or hyphen, max 64 characters. Files use relative POSIX paths; no parent traversal, .git or .auditagent scope. Never put secrets in JSON. These are data formats, not executable instructions.

## Finding: one object or an array

```json
{
  "id": "SEC-001",
  "title": "Project lookup lacks tenant ownership check",
  "domain": "security",
  "severity": "high",
  "classification": "confirmed",
  "confidence": "high",
  "evidence": [{"path": "src/projects.py", "detail": "get_project at lines 20-31 fetches by id without checking organization; verified against route caller."}],
  "impact": "A signed-in user may read another organization's project.",
  "recommendation": "Enforce tenant authorization in trusted request handling.",
  "verification": "Two tenants; test allowed same-tenant and rejected cross-tenant reads."
}
```

Severity: critical/high/medium/low/info. Classification: confirmed/suspected/optional/unverified. Confidence: high/medium/low. Missing-access findings can omit evidence path but must explain the gap in detail. Stable finding IDs are immutable; new evidence requiring revision gets a new ID with a supersession explanation.

## Plan

```json
{
  "version": 1,
  "summary": "Fix verified tenant access defect before adding features.",
  "phases": [{
    "id": "phase-1",
    "title": "Tenant access checks",
    "objective": "Reject cross-tenant project reads.",
    "finding_ids": ["SEC-001"],
    "allowed_paths": ["src/projects.py", "tests/**"],
    "tasks": ["Add authorization at the trusted route and cover both tenant cases."],
    "acceptance": ["Same-tenant read succeeds; cross-tenant read is rejected."],
    "checks": ["tenant-tests"],
    "depends_on": [],
    "risks": [],
    "rollback": "Revert the phase code diff in a reviewed change; no data migration.",
    "max_attempts": 2,
    "max_minutes": 30
  }]
}
```

Checks are exact labels, not shell command strings. Acceptance criteria are exact text and order, not paraphrased by verifier. Dependencies refer only to earlier phases. Approve a consecutive prefix of unfinished phases. Each phase requires findings (optional improvement findings are valid), nonempty tasks/acceptance/checks/scope, max_attempts 1..5 and max_minutes 1..480. Scope patterns use fnmatchcase; `*` can span slashes. Avoid ambiguous patterns. Deletions require delete_files risk. Risk flags: production/database_destructive/external_cost/delete_files/secret_rotation.

Load a revised plan only when no phase is active. Preserve verified phases exactly, including their IDs and placement/dependencies. Any load clears pending approvals and refreshes the source baseline; explicitly inspect the diff first. A new plan hash alone is not consent.

## Verifier report

```json
{
  "phase_id": "phase-1",
  "plan_hash": "COPY_CURRENT_PLAN_HASH",
  "snapshot_hash": "COPY_FINAL_STATUS_SNAPSHOT_HASH",
  "reviewer": "separate security verifier thread",
  "independent": true,
  "verdict": "pass",
  "acceptance": [{
    "criterion": "Same-tenant read succeeds; cross-tenant read is rejected.",
    "status": "pass",
    "evidence": "Reviewed trusted route ownership check and the tenant-tests recorded command; both tenant behaviors asserted."
  }],
  "limitations": "Local fixture database only; production configuration was not inspected."
}
```

Verdicts: pass/fail/blocked. Acceptance statuses: pass/fail/not_run. Pass requires all criteria pass and a successful recorded command for every check label on the final source snapshot. This does not prove checks are meaningful; a separate reviewer must inspect them. A report requires independent=true: if separate review unavailable, stop with an explanation instead of inventing a reviewer. Re-running checks after source changes is mandatory; test outputs that mutate source make earlier check records stale. Generated artifacts should remain in excluded folders.

## Project memory written by the coordinator

Keep `.auditagent/project-map.md` under approximately 1,000 words, `coverage.md` a short table (domain, scope, evidence, status, gaps), and `SUMMARY.md` generated by controller. Use `note` for a <=4,000 character current handoff. Preserve actual user decisions in the ledger; never chain-of-thought. Keep detailed logs outside the loaded summary, no secret values or customer data.
